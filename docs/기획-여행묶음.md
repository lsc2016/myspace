# 기획: "날짜" 탭을 여행 묶음 화면으로 바꾸기

먼저 CLAUDE.md를 읽고 시작할 것. 아래는 이번 작업의 범위와 원칙이다.

## 왜 바꾸나

달력 격자는 "언제"를 찾는 도구인데, 실제 쓰임은 "그 여행에 어디 갔나 / 어디 갈까"다.
식단 앱처럼 **왼쪽에 기간, 오른쪽에 장소 묶음**이 나오는 목록이 더 맞다.
용도 두 가지, 같은 틀로: (1) 다녀온 여행의 장소 기록 (2) 앞으로 갈 여행의 장소 선정.

## 개념 (주/부가 구분을 화면이 그대로 드러낼 것)

- **장소**가 主. 날짜 탭은 장소를 "기간으로 묶어 보는 방향"일 뿐.
- 묶음의 단위는 **여행** = 이름 + 시작일 + 종료일 + 그 기간의 장소들.
- 다녀온 여행은 기록, 아직 안 간 여행은 계획. 틀은 같고 "예정" 표시만 다르다.
- 여행에 안 묶인 날짜 기록은 하루짜리 묶음으로 그대로 보인다. 아무것도 사라지지 않는다.

## 1. 탭을 위로

- 아래쪽 `.tabs`를 없애고, 제목줄(`.top`) 바로 아래에 **장소 | 지도 | 날짜** 세그먼트(토글)를 둔다.
- 가로 화면(`body.wide`)에서는 지도가 항상 오른쪽에 있으므로 **장소 | 날짜**만 보인다. (기존 `body.wide .tabs button[data-tab="map"]{display:none}` 논리 유지)
- `switchTab`, `S.tab`, `data-tab` 구조는 그대로 두고 위치와 모양만 바꾼다.

## 2. 날짜 화면 (여행 목록)

- 달력(`.cal`, `.calhead`, `renderCal`, `shiftMonth`, prev/next/today)은 제거한다. 사용자가 안 쓰기로 했다.
- 목록 한 줄 = 여행 하나. 최근 것이 위.
  - 왼쪽 칸: 기간. 같은 해면 `10/19 – 10/21`, 하루면 `10/19`, 다른 해면 `2025. 10/19 – 10/21`. 종료일이 오늘 이후면 작은 **예정** 태그.
  - 오른쪽 칸: 여행 이름(없으면 첫 장소 이름), 그 아래 장소 미리보기 `산내들가든 · 악어섬 · 다원옥 …` 과 `N곳`.
- 여행에 안 묶인 날짜 기록은 그 날짜 하나짜리 묶음으로 같은 목록에 섞여 나온다 (이름 없음, "여행으로 묶기" 가능).
- 줄을 누르면 **여행 상세**가 시트(`openSheet`)로 열린다:
  - 제목: 여행 이름 (✎로 고치기), 기간, 예정 태그, 메모
  - 장소 목록: 날짜·시간 순, 번호(1,2,3…) 붙음, 분류 색 점, 장소별 날짜 기록 메모. 누르면 그 날짜 기록 편집(`openVisitEditor`, back='trip').
  - 버튼: **＋ 장소 넣기** / 지도에서 경로 보기(좁은 화면만) / 여행 정보 고치기 / 여행 삭제
  - 여행 삭제 = 묶음만 푼다. 장소의 날짜 기록은 남는다. 힌트로 적어 둘 것.
- **＋ 장소 넣기**: 내 장소 목록에서 고르면 날짜=여행 시작일로 **바로** 날짜 기록이 생긴다 (입력 최소화). 필요하면 나중에 그 기록을 눌러 날짜·시간·메모를 바꾼다. "＋ 새 장소로 추가"도 같이 둔다 (`openEditor(null,{date:시작일})`).
- 가로 화면에서 여행 상세를 열면 오른쪽 지도에 그 여행의 경로(1→2→3 번호 핀 + 선)가 바로 그려진다. 지도 위 배너는 "여행 이름 · 기간 · N곳".
- 떠 있는 ＋ 버튼(`#fab`)은 날짜 탭에서 **＋ 여행 추가**가 된다 → 이름·시작일·종료일·메모 입력 시트. 종료일 비우면 시작일과 같게.

## 3. 저장 구조

- 여행 목록은 **분류 설정과 같은 방식**으로 시트 `places`에 한 줄로 저장: id `__trips__`, memo 칸에 JSON 배열 `[{id,name,start,end,note}]`.
  `splitCats()`를 메타 줄 공용(`__cats__`, `__trips__`)으로 넓히고, `saveLocal`/`importMany`/`toMarkdown`에서도 메타 줄을 장소로 취급하지 않도록 할 것.
- 장소의 날짜 기록(`visits`)은 그대로. **날짜가 여행 기간 안에 들면 그 여행에 속한다.** 겹치는 여행이 있으면 시작일이 늦은(더 구체적인) 쪽. 어느 여행에도 안 들면 하루짜리 묶음.
- Code.gs는 손대지 않는다 (재배포 불필요).

## 4. 지도 연동

- 지금 `S.route`는 날짜 문자열 하나다. 이를 "경로로 그릴 날짜 기록 목록 + 라벨"로 바꿔서, 여행(여러 날)도 하루 묶음도 같은 코드로 그린다.
- `renderMap`의 경로 그리기, `#routeBanner`, 닫기 동작은 유지.

## 5. 건드리지 말 것

- 장소 탭, 선택 모드, 분류 관리, 한꺼번에 추가, 백업, 연결 링크, 내비 출발, 가로/세로 레이아웃 전환.
- 장소 상세의 "날짜 기록" 카드는 유지하되, 각 기록 옆에 속한 여행 이름을 작게 보여주면 좋다.
- 옵시디언 내보내기(`toMarkdown`)에 여행 단위 섹션을 추가하면 좋다 (선택).

## 6. 확인

- 좁은 화면(400px)과 넓은 화면(1133×744, 아이패드 미니 가로) 둘 다 스크린샷으로 본다.
- 시나리오: 여행 추가 → 장소 넣기 3곳 → 목록에 기간·미리보기 표시 → 상세에서 번호 순서 → 가로 화면에서 지도 경로 → 여행 삭제 후 장소 기록이 하루 묶음으로 남는지 → 새로고침 후 시트에서 다시 불러와도 여행 목록이 유지되는지.
- 끝나면 `git push`. 사용자는 아이폰·아이패드에서 새로고침해서 본다.
